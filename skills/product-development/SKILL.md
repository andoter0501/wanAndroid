# 产品开发流程

按固定阶段推进产品交付，并按顺序复用专业技能。

## 阶段 1：澄清范围

任何创意或产品类工作都先使用 `brainstorming`。

执行内容：
- 明确目标用户、核心场景、业务目标。
- 定义 MVP 边界，并明确列出非目标范围。
- 定义成功指标与验收标准。

产出物：
- 简版产品说明，包含 `goals`、`users`、`MVP`、`non-goals`、`success metrics`。

## 阶段 2：设计体验与原型

使用 `Prototype Designer`。

执行内容：
- 基于功能构建信息架构。
- 先设计关键用户流（主路径 + 关键异常路径）。
- 先产出低/中保真原型，再进入高保真打磨。
- 每个核心页面都要覆盖加载、空态、错误态、离线态。

产出物：
- 页面结构图（Screen Map）。
- 用户流图（Flow Map）。
- 原型可用性验证清单。

## 阶段 3：定义视觉方向

交互流程稳定后使用 `frontend-design`。

执行内容：
- 定义视觉系统 Token：颜色、字体、间距、圆角、动效。
- 若已有设计系统，保持与平台规范一致。
- 避免通用模板化设计，视觉需贴合产品领域与用户预期。

产出物：
- 组件与状态的 UI 规范说明。
- 可复用组件优先级清单。

## 阶段 4：映射接口与架构

使用 `architecture-designer`。

执行内容：
- 将每个页面/流程映射到 API 接口与状态流转。
- 明确模块边界：`network`、`domain`、`ui`、`storage`。
- 定义错误处理与重试策略。
- 涉及登录时，定义鉴权与会话管理策略。

产出物：
- 功能到接口映射表。
- 数据流说明。
- 架构决策与权衡记录。

## 阶段 5：实现开发

使用 `Code`。

执行内容：
- 按纵向切片实施（一次完成一条用户流）。
- 保持提交粒度小且可验证。
- 复用共享组件，避免重复状态逻辑。

产出物：
- 可运行的功能切片，具备清晰集成点。

## 阶段 6：验证与加固

使用 `test-runner`。

执行内容：
- 为领域逻辑与接口解析补充单元测试。
- 为加载、成功、空态、错误分支补充 UI/状态测试。
- 合并前执行核心流程回归检查。

产出物：
- 测试结果摘要。
- 剩余风险与后续任务列表。

## 标准交付汇报格式

汇报进度时始终包含：
1. 当前阶段与完成状态。
2. 本阶段产出物。
3. 阻塞问题与明确下一步动作。
