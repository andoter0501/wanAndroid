# wanAndroid 鸿蒙客户端产品简报（完整版 MVP）

## 1. 目标
- 基于 wanAndroid 开放接口，交付一款可用的 HarmonyOS 手机端内容客户端。
- 覆盖文档中的主要能力：内容浏览、搜索、登录体系、收藏、广场、问答、积分、消息、个人中心。
- 建立可持续迭代的模块化架构，支持后续平板/折叠屏扩展。

## 2. 目标用户
- 鸿蒙开发者与技术内容消费者。
- 需要按技术分类、项目、问答快速获取内容的移动端用户。
- 需要账号能力（收藏、积分、消息、分享）的活跃用户。

## 3. MVP 范围（你已确认：完整版）
- 首页：Banner、置顶、文章流、热门板块、鸿蒙专栏入口。
- 体系/导航/项目：分类浏览与分页列表。
- 搜索：热词、关键词检索、搜索结果分页。
- 登录体系：登录、注册、登出、会话恢复。
- 收藏体系：收藏文章/站外文章、编辑、取消、收藏网站管理。
- 广场体系：广场列表、他人分享、我的分享、分享与删除。
- 问答：列表与评论列表。
- 个人中心：积分、个人信息、站内消息（未读数/已读/未读列表）。

## 4. 非目标（本轮不做）
- 平板/折叠屏专属布局优化。
- 离线全文缓存与本地全文检索。
- 推送通知服务端联动。
- 深度社交互动（评论发布、点赞等扩展能力）。

## 5. 成功标准
- 核心路径成功率：未登录浏览 + 登录后收藏 + 搜索 + 消息查看全流程可用。
- 性能目标：首屏可交互时间 < 2.5s（正常网络），列表翻页无明显卡顿。
- 稳定性目标：核心页面崩溃率 < 0.3%。
- 数据一致性：登录态与收藏态跨页面同步正确，`errorCode = -1001` 自动触发会话失效处理。

## 6. 默认产品策略（直接执行）
- API 基础地址统一使用：`https://wanandroid.com`（不带 `www`）。
- 分页起始按接口文档执行，不做全局统一假设。
- 全局错误处理以 `errorCode != 0` 判失败；`-1001` 统一进入登录失效流程。
- 手机端优先，采用底部导航 + 页面内二级导航信息架构。
